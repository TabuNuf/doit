# T-027.1: A task carries agent, model and effort, kept in its task file

## Description

For: batch-builder, Sonnet 5.5, medium

Goal: a task has `agent`, `model` and `effort`, null when unset, written to the task file front matter. Design: `Docs/Design/Design.md`, section Tasks, "Who builds it".

Steps:
1. `src/domain/task.js`: export `EFFORTS = ["low", "medium", "high", "xhigh", "max"]`; `defaultsFor` returns the three as null; one exported function holds the checks for both add and update: agent and model are free text through `oneLine`, empty becomes null; effort is empty (null) or one of `EFFORTS` through `check(EFFORTS, value, "effort")`.
2. `src/domain/taskEdit.js`: cases `agent`, `model`, `effort` using that function.
3. `src/domain/board.js`: `addTask` takes `agent`, `model`, `effort` with the same checks. The file is at 218 lines and `test/structure.test.js` fails at 220: add no lines.
4. `src/store/markdown.js`: add the three to `FIELDS` after `contact`.
5. `src/domain/activity.js`: `describeChanges` names a change to any of the three, if it names fields one by one.
6. `Docs/Architecture.md`: the lines on `task.js` and `taskEdit.js` and the class diagram.

Limits: a change of owner never touches the three fields. A task file without the keys loads with nulls.

Tests (new `test/assignment.test.js`, set up like `test/domain.test.js`): add with the three and read back through a fresh Board; update sets each and clears each with ""; `effort=huge` throws a message listing the five; owner ai to human to ai keeps all three in the Board and in the task file text; `parseTaskFile` on text without the keys, then `formatTaskFile`, round-trips.

Commit as `T-027.1: <summary>`, staging only your paths. Run `npm test` and report its output. The task is done only when it passes.
