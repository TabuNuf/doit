# T-033.8: Rating: creator profile, points and tier

## Description

Goal: one pure function rates a contact for a game profile, so every list orders the same way.

Add `src/domain/rating.js`, pure, its limits as named constants. `creatorProfile(games, today)`: from covered games dated within 12 months that have a type and all six scores, `{counted, shares, scores}` (share per type, six averages). `rate({games, profile, typeList, comps, today})` returns `{tier, points, parts: {type, persona, comps}, persona, counted}`. Type, 0 to 4, from the summed `typeWeight` share: 0.6 gives 4, 0.4 gives 3, 0.2 gives 2, above 0 gives 1. Persona, 0 to 3, from the smallest summed difference between the six averages and a persona's scores: up to 3 gives 3, up to 5 gives 2, up to 7 gives 1; it names that persona, and a profile without personas gives 0. Comps: one point per covered comp title, 2 at most. Tier: 7 `strong`, 4 `good`, else `long shot`; `counted` under 3 stops at `good`. `compareRatings(a, b)` orders by tier, then points.

Where T-033.4 changed a number in the epic's Specification, use that number.

Run `npm test` and report its output. The task is done only when it passes.
