# T-033.10: Ratings facade, wired in the root, with doit rating

## Description

Goal: one facade answers who suits a game and how well, so the weekly list, the campaigns and the page all ask the same place.

Add `Ratings` in `src/domain/ratings.js` over the `ContactBook`, the `GameCatalog` (comps and the types port) and a clock. `forGame(game)` gives every shown person with a rating, best first (`compareRatings`, then reach), each `{id, name, reach, rating, replied, lastAbout, last}`. `of(contactId)` gives one rating per game profile. A fit may carry a tier set by hand, which wins over the computed one: `doit fit <id> <game> <reason> --tier strong|good|long-shot`. Wire it in `src/root.js` and hand it to the CLI and the server. Add `doit rating <game> [--tier t] [--limit n] [--json]`, the rating lines in `doit contact show`, `GET /api/ratings?game=<game>` and `GET /api/contacts/:id/ratings`.

Limits: `ContactBook` and `GameCatalog` never import `ratings.js`, and `test/boundaries.test.js` must pass. You may add a read method to either facade when `Ratings` needs data they hold. You may add one migration step for the fit's tier.

The proof is `npm test` passing and `node bin/doit.js rating bunny-bunker --limit 5` printing five rated people.
